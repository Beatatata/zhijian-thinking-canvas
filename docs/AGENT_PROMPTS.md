# 可复制的开发提示词

先打开对应项目目录，再将下列提示词交给你的 coding agent。把方括号内容改为实际需求。

## 实现一个功能

```text
你在枝间 Thinking Canvas 项目中工作。先读 README.md、CONTRIBUTING.md、docs/DEVELOPMENT.md、SECURITY.md 和适用的 AGENTS.md，再检查现有实现。
需求：[明确写出用户操作、当前问题和期望结果]。
保持本地优先，不上传个人工作台，不引入账号、云同步、追踪或第三方服务。沿用 React / TypeScript / Vite / Tabler Icons，正文在外层仅阅读、链接可跳转；正文格式与内容只在双击进入的专注编辑里修改。标题、清单和表格沿用现有直接操作。
先找根因再修改，沿用现有架构。检查旧备份兼容、复制、撤销、分栏布局和导出，避免把修复只应用到一种卡片。
使用通用教学数据验证，不操作真实个人工作台。运行相关测试和生产构建；涉及交互时在浏览器验证实际路径，并保存只含示例数据的截图。更新必要文档。最后说明改动、验证和未解决限制。不要未经授权发布仓库或更改网站访问范围。
```

## 修复 UI 或拖动问题

```text
请改善枝间的 [模块]。参考图：[路径或附件]。
先读 docs/DEVELOPMENT.md，检查事件冒泡、pointer capture、world 坐标、缩放换算、布局与最终 CSS 层级，明确问题根因。不要通过隐藏内容或强制固定高度掩盖问题。
保留标题点击编辑、输入法、整卡拖动、分栏自动撑高、浅深色和键盘焦点行为。采用 Tabler 图标与已有设计语言，避免新增无必要说明。
用教学数据验证拖动、缩放、复制、撤销、长内容和嵌套布局。类型检查、相关测试与构建通过后交付；如要发布，先确认对应站点及已授权范围。
```

## 审查一项贡献

```text
审查当前 diff，先读 CONTRIBUTING.md、SECURITY.md 和 docs/DEVELOPMENT.md。重点检查可复现的数据丢失、旧备份不兼容、输入／拖动冲突、导出注入和同步覆盖。不要泛泛评价风格。
必要时运行相关验证，报告具体复现步骤、文件位置、影响和优先级。不要修改或上传个人工作台数据。
```

GitHub 发布提示词单独见 GITHUB_PUBLISH_PROMPT.md。
